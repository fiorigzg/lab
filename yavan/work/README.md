# Корпус яванского языка - что и в каком порядке было сделано

Дата работ: 2026-06-10. Проект по инструкции из `../instruction/`
(mail.md + Notion-инструкция «Инструкция по работе с текстами»).

Весь пайплайн ОБРАБОТКИ (очистка, лемматизация, эмбеддинги, аналитика) лежит
в нутбуке `process_corpus.ipynb` и запускается сверху донизу. В `scripts/`
остались только скрипты СБОРА сырого корпуса (скачивание и одноразовая чистка
обвязки сайтов) - сырой корпус из нутбука невоспроизводим. Прежние
обработочные скрипты (`clean_corpus.py`, `build_lexicon.py`,
`jav_lemmatizer.py`, `lemmatize_corpus.py`) удалены: их код теперь в нутбуке,
причём в обновлённом виде.

## Карта папок

| Путь | Что лежит |
|---|---|
| `process_corpus.ipynb` | Канонический пайплайн: очистка + лемматизатор + эмбеддинги (SVD, CBoW) + аналитика с графиками. Самопроверяющийся (есть тест трёх требований к лемматизатору) |
| `SOURCES.md` | Реестр источников: что нашли, откуда качали, лицензии, что исключается из обработки и почему |
| `scripts/` + `scripts/README.md` | Скрипты СБОРА сырого корпуса: скачивание + одноразовая чистка обвязки сайтов. Обработка - в нутбуке |
| `corpus_raw/` | СЫРОЙ корпус: 3813 txt, ~26.7 млн слов; 1 файл = 1 текст, имя файла = название текста; метаданные `_metadata*.tsv` в папке каждого источника |
| `corpus_clean/` | ОЧИЩЕННЫЙ корпус (без лемматизации): `texts/<ведро>/` - тексты по одному файлу; `corpus_text_<ведро>.txt` (1 строка = 1 текст, для SVD); `corpus_segments_<ведро>.txt` (1 строка = 1 предложение, для CBoW); `_excluded.tsv`, `_stats.txt` |
| `corpus_lemma/` | То же, но ЛЕММАТИЗИРОВАННЫЙ (та же структура): тексты по файлам, текстовый и сегментный корпуса по вёдрам, `_stats.txt` со сжатием словаря |
| `lexicon/` | Корни `roots.txt` (~22 тыс.) и частоты `freq.tsv` - ресурс лемматизатора (строится в нутбуке) |
| `embeddings/` | Эмбеддинги ведра sastra: `svd_sastra_32.npy` (SVD, <= 32) и `cbow_sastra_100.txt`/`.kv` (CBoW, 100) |
| `eval/` | Трибанк UD Javanese-CSUI (`jv_csui-ud-test.conllu`) для оценки лемматизатора |

Вёдра (источники/регистры не смешиваем): `sastra` - литература (основной
корпус), `jurnal` - журналы 1920-30-х (запас), `arsip` - архивы (запас),
`majalah` - Panjebar Semangat 2010-х (запас).

## Хронология шагов

### Шаг 0. Проверка готовых корпусов и инструментов (п.1 инструкции)
Готовые корпуса яванского: CC-100/OSCAR/Leipzig - веб-краулы и Википедия,
не подходят (нужна литература). Корпус журнала Panjebar Semangat (Mozilla
Data Collective, ~1.7 млн слов, CC-BY-SA) - найден, скачивание требует
регистрации; оставлен как запас. Готового лемматизатора яванского нет
(spacy-модели нет; написан свой). Детали - в `SOURCES.md` §5.

### Шаг 1. Поиск источников литературы
Критерии: не Википедия, местная литература (сказки, классика, местные
авторы), в крайнем случае местные статьи. Найдено и использовано три
источника: sastra.org (Yayasan Sastra Lestari - крупнейшая библиотека
оцифрованной яванской литературы), alangalangkumitir.wordpress.com
(транскрипции серата/сулуков/бабадов), ki-demang.com (современные
рассказы-cerkak и романы). Полный список включая отвергнутые - `SOURCES.md`.

### Шаг 2. Скачивание сырого корпуса -> `corpus_raw/`
1. **alangalangkumitir** - 672 поста через публичный API wordpress.com
   (`scripts/download_alangalangkumitir.py`).
2. **ki-demang** - литературные разделы, прямой скрейпинг
   (`scripts/download_kidemang.py`).
3. **sastra.org** - 3036 из 3038 уникальных страниц (2 оставшиеся текста
   не содержат). Сайт блокирует нашу сеть, поэтому два канала параллельно:
   снапшоты Wayback Machine по списку из CDX API
   (`scripts/download_sastra_org.py`, поддержаны 4 версии вёрстки сайта
   2013-2025 гг.) и живой сайт через прокси r.jina.ai с конца списка
   (`scripts/download_sastra_live.py`). Имя файла = slug страницы
   (название произведения, автор, год, ID).

### Шаг 3. Чистка обвязки сайтов в сыром корпусе (одноразовая)
Удалены служебные элементы страниц (меню, календарь, подсказки поиска,
подвал) - текст произведений не тронут:
`scripts/sweep_sastra_furniture.py`, `scripts/clean_jina_chrome.py`.

### Шаг 4. Очистка корпуса -> `corpus_clean/` (в нутбуке)
Без лемматизации. По порядку: исключение словарей/грамматик и прочего
нетекста (нотации гамелана, сканы-заглушки - всего 792 исключения, см.
`corpus_clean/_excluded.tsv`); удаление артефактов оцифровки (маркеры
страниц `--- N ---`, сноски, редакторские пометки, обрывы слов); построчный
фильтр языка (яванский остаётся; индонезийский/голландский/английский -
вон); нормализация (lowercase, диакритика ê->e и т.п., довоенная орфография
oe->u, tj->c, dj->j); замена цифр -> ORDINAL1 и местоимений -> PRON1 (по
инструкции); сегментация на предложения (.?!; и стиховые разделители | и ||).

Результат (после добора, шаг 5): sastra - 2105 текстов / 2 254 719
предложений / 13.83 млн токенов; jurnal - 682 / 299 590 / 3.83 млн;
arsip - 386 / 181 199 / 1.63 млн; majalah - 2224 / 126 512 / 1.23 млн.
QC: иноязычных примесей в основном корпусе ~0.01% предложений (строгий счёт
по однозначным стоп-словам).

### Шаг 5. Проверка полноты и добор (2026-06-11)
По вопросу «всё ли скачано из найденных источников»:
- **ki-demang**: найдены 6 пропущенных разделов меню «naskah kina»
  (Negarakertagama, Pararaton, Ramayana, suluk-padhalangan,
  sinopsis-pakeliran, puspawarna) - добрано.
- **alangalangkumitir**: сверка с API - все 672 поста на месте.
- **sastra.org**: сверка с официальной статистикой сайта (июнь 2026:
  2653 коллекции); листинги живого сайта рендерятся JS и через прокси
  видны не полностью (`scripts/check_sastra_completeness.py`, +2 статьи),
  поэтому добор - перебором дыр в нумерации ID статей через
  `index.php?...&id=N` (`scripts/probe_sastra_ids.py`) ->
  `corpus_raw/sastra-org/_recovered/`.
- **Panjebar Semangat** (журнал, по нормативу инструкции «идеально
  5-10 тыс. текстов» решено добрать): ~2600 статей 2010-2019 из Wayback
  (`scripts/download_panjebarsemangat.py`); живой домен с ~2020 г.
  захвачен спам-сайтом, берутся только снапшоты до 2020 г. Идёт в
  отдельное ведро `majalah`.
- **djakalodang.co.id** проверен и отброшен: в архиве только пустые
  анонсы номеров, статей нет (см. SOURCES.md §5).
После добора очистка перегнана заново (ведро `majalah` добавлено в нутбук;
`_recovered`-статьи раскладываются по вёдрам по названию).

### Шаг 6. Лемматизация -> `corpus_lemma/` (в нутбуке)
Готового лемматизатора яванского нет - написан свой, на правилах. Принцип:
снимаем ИНФЛЕКСИЮ (грамматику - формы одного слова склеиваются: nulis,
ditulis, tulisane -> tulis/tulisan), а ДЕРИВАЦИЮ (номинализатор -an,
каузатив -ake, аппликатив -i - меняют значение) оставляем отдельными
леммами: tulisan != tulis, inuman != inum. Штили (krama/ngoko) лексически
не сводим: mangan / nedha / dhahar - три леммы (корни разные). Частые
служебные и лексикализованные слова, которых нет в словарях, защищены
отдельно, чтобы их не портили назальные правила (minangka не -> mangka).

Лексикон корней (~22 тыс., `lexicon/roots.txt`) собран из словарей, лежащих
в сыром корпусе (Horne 1974, Gericke & Roorda 1847, dasanama) - они
исключены из текстового корпуса, но пригодились как ресурс.

Оценка на UD Javanese-CSUI (золотые леммы): точное совпадение с эталоном
82%, ложных замен 1.6% (хороших замен - точных и частичных - 79%);
расхождения в основном это намеренный отказ сводить деривацию (UD её сводит)
и пробелы лексикона, а не ошибки. Прогон по корпусу: словарь ведра sastra
сжался с 401.6 тыс. до 315.2 тыс. типов (-22%; меньше «слепого» стемминга,
зато без порчи смысла). Структура `corpus_lemma/` повторяет `corpus_clean/`.

### Шаг 7. Эмбеддинги -> `embeddings/` (в нутбуке)
Считаются по основному ведру sastra, метод как в примерах инструкции.
- **SVD** (<= 32) по текстовому корпусу `corpus_lemma/corpus_text_sastra.txt`:
  TF-IDF (тексты x слова) -> `scipy.sparse.linalg.svds` (random_state
  фиксирован для воспроизводимости) -> словарь {слово: вектор} в
  `svd_sastra_32.npy` (~60 тыс. слов).
- **CBoW** по сегментному `corpus_lemma/corpus_segments_sastra.txt`:
  `gensim Word2Vec` (sg=0), 100 мерностей -> `cbow_sastra_100.txt` (формат
  «слово вектор», первая строка «N dim») и `.kv` (~73 тыс. слов). Для
  воспроизводимости workers=1, seed=0, запуск с PYTHONHASHSEED=0.
- Валидация обоих (в нутбуке): ближайшие соседи осмысленны (у CBoW - прямые
  синонимы); регистровые пары (ratu/raja, banyu/toya, mangan/dhahar)
  получают близкие векторы - это подтверждает решение держать krama/ngoko
  разными леммами.
